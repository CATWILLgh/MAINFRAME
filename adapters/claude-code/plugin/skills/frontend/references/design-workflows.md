# Work type

Choose one branch after selecting the surface mode.

First inspect enough of the repository and current interface to separate an engineering choice from a product choice. Resolve engineering details from evidence. Escalate only a choice that changes product behavior, business meaning, infrastructure, or the explicitly assigned visual direction.

## Preserve or refine an established surface

Inspect nearby screens, tokens, primitives, interaction patterns, and tests. Preserve their language. Fix the assigned flow with the smallest coherent extension; do not turn local work into a redesign.

## Build a new surface inside an established product

Reuse the closest existing shell, navigation, tokens, primitives, content patterns, and state handling. Define the user journey and reachable states before styling. Introduce a new visual rule only when existing rules cannot express the need.

## Establish a new visual direction

Use this branch only when the product has no adequate established language or the assigned work explicitly asks for a new one. Ground the direction in the subject, audience, user job, content, and operating constraints. Compare a small set of meaningfully different directions when the choice is genuinely open; do not generate a fixed quota of concepts or use randomness as a substitute for reasoning. Record the chosen durable decisions in the project's existing design source of truth when one exists or when creating one is part of the task.

## Redesign an assigned surface

Record the current user goal, content, constraints, and failure states before changing structure. Choose an explicit mode and visual direction, preserve business behavior unless its change is assigned, and compare old and new journeys with representative data.

## Audit

Observe rather than restyle by preference. Report a concrete mismatch between user purpose and evidence: blocked task, missing state, inaccessible interaction, inconsistent primitive, broken hierarchy, responsive failure, or needless cognitive load. Do not convert taste into a defect or combine unlike findings into a pseudo-precise score. Use [review and evidence](review-and-evidence.md).

For every branch, verify the changed journey rather than only the default screenshot. Keep the iteration bounded: inspect representative states, fix one coherent batch, and verify the affected path again. If project evidence and an external convention conflict, preserve the product contract unless it is unsafe, inaccessible, or the task includes changing it.

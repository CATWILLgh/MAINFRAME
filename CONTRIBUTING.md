# Изменение хаба

Сначала прочитайте [принципы](docs/principles.md). Сохраняйте полезный результат
заготовки; нативный формат выбирает устанавливающий агент по своей документации.

- Тексты, предназначенные агентам, пишите на английском. Объяснения оператору —
  на русском. Не навязывайте язык общения пользователям других проектов.
- Добавляйте скилл для самостоятельного полезного метода. Длинные условные
  ветви размещайте в связанных references; скрипт добавляйте для оправданной
  детерминированной операции, а не для управления адаптерами.
- Держите одну исходную версию метода, доступную любому исполнителю. Роль и
  полномочия задаются конкретным поручением.
- Для хука сохраняйте рабочий исходник с нужными помощниками. Кратко опишите
  назначение, точки адаптации, событие по смыслу, границу отказа, обычный успех,
  ошибки и проверочные случаи. Не выдавайте эвристику за техническую защиту.
- Добавляя или удаляя материал, обновите [пример прогресса](examples/progress.json).
  Один скилл включает свои ресурсы; достаточно одного `done: false` на единицу.
- Изменение инструкции требует проверки её смысла в контексте. Совпадение слова
  не доказывает вред. Установка должна проверить фактическую загрузку и работу.
- Не добавляйте адаптеры, установщики, компиляторы, телеметрию или постоянный
  журнал прохождения. Сохраняйте чужие настройки, личный каталог и секреты.

Перед завершением выполните `python3 scripts/check-hub.py` и
`git diff --check`. Проверяйте изменённое поведение скриптов подходящим локальным
примером; не называйте структурную проверку доказательством качества модели.
Локальные коммиты остаются локальными, пока публикация явно не запрошена.

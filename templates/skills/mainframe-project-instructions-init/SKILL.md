# Initialize project guidance

First consult the current official documentation for this product's project
instructions, skills, inheritance, precedence, and supported working surfaces.
Discover the actual project and inherited global guidance through those native
contracts. Do not infer another product's filenames or loading rules.

Inspect the effective instruction chain for representative working directories.
Preserve existing project knowledge and user-owned configuration. Keep global
configuration read-only during a project setup task.

Give each durable rule one owner. Put shared project invariants in the smallest
native root layer, substantial reusable methods in discoverable skills, and
subtree exceptions in the documented narrower layer. Do not duplicate the
installed skill catalog or preload every skill body. Link relevant resources
and keep project facts separate from general methods.

Resolve ordinary organization and wording within the authorized setup. Surface
conflicts that change product meaning, authority, or user choices before
resolving those meanings. Do not make routine file placement another approval
stage when the user has already authorized setup.

Reconstruct the final effective chains, resolve every reference, and measure
the always-loaded footprint against actual native limits. Check discovery and
representative use where possible. Report what changed and what was verified;
static structure alone does not prove long-session instruction quality.

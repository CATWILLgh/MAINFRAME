# Author instructions for the actual recipient

First consult the current official documentation for the affected product
layer and its model prompting guidance. Establish who receives the text, when
it loads, precedence, native limits, and whether it is repeated elsewhere.

Preserve the intended outcome, authority, evidence, and completion boundary.
Use the smallest layer whose recipients need the rule. Keep skills available
to any agent assigned matching work; role briefs bound a particular task rather
than own access to the method.

Write each rule once in the effective context. Describe observable decisions
and results. Prescribe a fixed sequence only when order protects correctness.
Reserve absolute language for real invariants. Replace vague quality demands,
blanket tool pressure, and repeated permission requirements with the condition
that changes the decision. Do not request private chain-of-thought.

Discovery descriptions say what the capability does, when to select it, and
the nearest confusing alternative. Execution instructions belong in the body;
conditional detail belongs in linked resources. Avoid hardcoded native fields,
model names, and specialist identifiers in portable source.

Check semantics in the complete effective context, not through keyword bans.
Verify native parsing, links, loading, and a realistic task plus its nearest
misroute. Test direct and delegated recipients when available. Keep structural
validation distinct from observed model behavior, and do not claim independent
review for a self-check.

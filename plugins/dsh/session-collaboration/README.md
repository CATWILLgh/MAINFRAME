# Session collaboration

MAINFRAME plugin **0.5.1**, pinned to DSH **0.2.2-rc.1**. One parameterized native tool coordinates ordinary conversations across projects, creates independent sessions, selects session-local models, and archives/unarchives sessions. No subagent spawning, global model-default changes, goal activation, forced stop or permission bypass.

## One tool, progressive actions

Call `collaboration` with a required `action` and only that action's fields. No MCP server, hidden setup or legacy aliases are needed. Agent-facing schemas, errors and peer envelopes are English regardless of UI language.

| Action | Purpose |
| --- | --- |
| `list_projects`, `list_sessions` | Discover projects and ordinary sessions without waking Agents; distinguish live idle from unloaded. Archived conversations opt-in. |
| `read` | Bounded selected history, state and optional goal without activation. |
| `send` | Enqueue peer context (`followup` default, or `steer`), optionally waking a cold target. Returns stable `taskId` and native `afterSeq`. Optional `label`/`group` support discovery. |
| `wait` | Observe 1–8 distinct `targets`, `any` or `all` (default), within one shared deadline. The singleton uses the same array shape. Stops observations only. |
| `list_tasks`, `get_task`, `cancel_task` | Caller-owned send metadata. Cancel affects observations/notices, **never target execution**. |
| `models` | Progressive, paged provider → model → exact reasoning-effort discovery, without a model run. |
| `create`, `archive`, `unarchive` | Create in an existing project; archive/unarchive another ordinary session. Archive checks inactivity without forcing work to stop. |
| `get_model`, `set_model` | Inspect or select one session's model; never change deployment defaults. |

For example: `{"action":"list_projects"}`, then `{"action":"list_sessions","workspaceId":"<returned-id>"}`. After send, observe with `{"action":"wait","targets":[{"sessionId":"<target-id>","afterSeq":42}]}` using the returned cursor, not the example value. Unknown fields, invalid action/field combinations and invalid nested targets reject before dispatch. The eight 0.4.0 tool names are no longer registered.

List → optionally read → send scoped requests with a common group → continue independent work. A session-window notice returns asynchronously. Use `notify:false` for replies/acknowledgments to avoid loops. Use send's `afterSeq` for manual waits; it is sampled before the durable pre-enqueue write, not an atomic inbox position. Tasks report observations, not delegated work success.

## Session lifecycle

- Discover an existing project with `collaboration({action:"list_projects"})`, then call `collaboration` with `{action:"create", workspaceId}`. Empty projects work. A missing project or unavailable directory rejects before creation; directory status is a preflight, not a filesystem transaction. Only `{workspaceId}` reaches public `sessionController.create`: no session reuse, cwd override, ancestry/origin, title or preset option. Native creation mounts the deployment's configured default preset and returns its selection when present; this is not an inferred per-project preset. The new session is independent and idle; the plugin sends no prompt/message, starts no model turn and rearms no goal. Configured preset initialization remains native-owned.
- Prefer `{action:"create", workspaceId, title:"Review installation"}` for agent-created sessions. Optional `title` accepts 1–200 Unicode code points and must normalize to visible text. The native title service applies its own normalization/byte limit and **pins** the accepted name against future automatic title generation. Success returns the accepted `title` and `titleStatus:"applied"`. Omission preserves old behavior and does not resolve an Agent for naming; peer-only conversations may stay unnamed because native auto-title requires genuine human input. No message source is spoofed: native `session/title` metadata is distinct from a human `user/message`.
- Naming and optional model selection are independent, non-atomic post-create operations. Uncertain naming returns `created-title-unknown`, uncertain model selection `created-model-unknown`, both `created-configuration-unknown`, always retaining the created ID and any confirmed sibling result. `titleStatus:"unknown"` means naming was not confirmed (possibly not attempted); an exception may occur after persistence. Inspect the directory/GUI rather than recreating, renaming again automatically, or deleting.
- Create returns `outcome:"created"` and the native session ID. Native attachment failure with explicit identity returns `created-unattached`; other attempted failures return `unknown`. **Never automatically retry creation**: creation can commit before an exception, cancellation, process exit or lost response. Inspect the session directory first. There is no idempotency/replay ledger, rollback or deletion.
- Discover archived IDs with `includeArchived:true`, then use `{action:"unarchive", sessionId}`. Only public `workspaceRegistry.unarchiveSession(id)` runs: no activation, message, goal rearming or history change. Ordinary forks are eligible; missing, self and subagent targets reject. Native repeated unarchive is idempotent. A failed native call returns `unknown`, not false success.
- `archive` uses public `workspaceRegistry.archiveSession(id)` **without `stopActivity`**. Passive state and final live-input checks reject observed running, queued or pending input; native activity checks also cover jobs, subagents and scheduled activity. No target is loaded just to archive it, and the plugin sends no stop/clear request. This intentionally follows native snapshot semantics, not the stronger restriction in 0.4.0. **It is not an atomic inactivity lock:** activity can begin between the check and durable archive. A running step may become hidden; a racing input can also be claimed by the native loop and then rejected by archive admission before transcript commitment. This is a real native input-loss edge case, not a guarantee that no work is affected. Avoid archiving a session that another actor is about to prompt. The plugin does not emulate locks or automatically unarchive on a race; either could lose queued input or undo an unrelated user action. Inspect uncertain outcomes before retrying.
- All lifecycle actions require the exact live caller. Inputs have no force/delete option. Cancellation or caller replacement observed during preflight prevents mutation. Once a native mutation is entered it is not cancellable; disposal drains the actual promise and does not claim rollback.

## Session-local models

Use `collaboration({action:"models"})` for registered providers, add `{provider}` for that provider's advertised models, and `{provider,model}` for exact reasoning efforts and the adapter's declared default, if any. Pages default to 30, max 100, and return IDs/names rather than full catalogs. Missing reasoning metadata means no advertised effort, not an invented capability; discovery failures are visible.

- `create` optionally accepts paired `provider` and `model` plus `reasoning_effort`. `set_model` requires the pair and another unarchived ordinary `sessionId`. Unknown providers/models and unsupported explicit efforts fail before create/resolve/selection. Native `llm.resolveCallConfig` performs exact effort validation; its materialized defaults are deliberately not persisted.
- **Omit `reasoning_effort` for Auto**, including when switching models. It never inherits the old model's effort. There is no synthetic `auto` ID: only discovered IDs may be explicit.
- `set_model` may resume a cold Agent but starts no prompt, model run or goal. It calls the public Agent's complete `model.select` with the requested choice, never `sessionController.selectModel` (that API also saves the deployment default). Success returns `selection`, `appliedFrom:"next-unprepared-step"`, `defaultChanged:false`; an already prepared/running step is unaffected. Native Agent selection records `model/selection` for ordinary resume; the plugin owns no duplicate persistence.
- `get_model` reads only a live Agent's public `model.current()`. Cold sessions return `outcome:"unknown",loaded:false`, without activation or inference from global defaults. A live choice is not necessarily the prepared step currently running.
- Creation and subsequent model selection are not atomic. A configuration failure preserves the fresh ID as `created-model-unknown`; inspect that ID and repair with `set_model` if needed, **never recreate automatically**. An uncertain set returns `unknown` and instructs inspection. Native attachment failure can leave a created session unconfigured. There is no rollback, delete, default update or force stop.
- Model operations share the lifecycle drain: cancellation before admission prevents mutation; once native resolve/create/select begins, that actual native promise is drained even if the caller cancels or the plugin unloads. Read-only metadata waits are abort-raced, including post-resolution revalidation on disposal; this can return an explicit partial/unknown configuration outcome while preserving the created ID. Scope and target identity are checked before selection; archive checks are preflights, not a native atomic archival lock. This public API cannot coordinate atomically with the GUI's private image-admission guard; selection does not establish compatibility with prior image history.

## Authority and effects

Native inbox messages use `createUserMessage` with `source.kind: 'session-collaboration'`, never human source `user`. Their native transcript role is `user`; that does not confer human authority. Peer history and labels are contextual data. Nothing changes goals or calls `sessionController.prompt`. Sending may spend tokens or trigger ordinary target tools under existing policy. Cold activation uses native `resolveAgent`; newly resumed goals remain disarmed. The plugin never disposes Host-owned Agents.

Peer envelopes put message content first and concise source/authority/reply guidance in a footer. Replies use `notify:false` to avoid automatic notice loops. Queue previews therefore lead with useful content, but the footer is not completely hidden: DSH 0.2.2-rc.1's public queue text slot passes whitespace facts, not trusted message-source metadata. A text-only hiding rule could mask ordinary user text, so no such Client hook is installed. Tool schemas, results and Agent-facing envelopes are English. Plugin metadata has Russian and English locale files; other locales fall back to English.

Self-send, archived and child/subagent targets are rejected; ordinary forks remain valid. No cold caller is resumed to notify. Notice delivery is allowed only for an exact live Agent that has naturally entered a model step (or invoked send). After restart/replacement, even an opened idle caller waits for its **next natural step**; safe pre-step handling preserves the native decision unchanged. Previously admitted live idle callers may be woken by a notice. Exact identity, archive state and abort signals are rechecked after the durable notice claim.

## Durable coordination and crash semantics

The public `storageDomain` service owns one schema-validated domain, `mainframe_session_collaboration`, version 1. Only bounded IDs, native cursors, timestamps, statuses, short labels and notification state are stored. **No message bodies, transcripts, output snapshots, error strings, permanent execution logs or send replay.** Native session logs remain the source for content. Labels are user/model supplied metadata, max 120 characters each; do not put sensitive message content in them.

- Every send persists a prepared task before target activation/enqueue. Initial storage failure prevents sending. Restarted prepared tasks become `delivery: unknown`; no resend or target activation occurs. An inbox exception is likewise ambiguous, not proof of non-delivery.
- Native inbox enqueue and metadata writes are not atomic. If enqueue succeeds but its acknowledgement write fails, the tool returns `accepted:true` with a persistence warning, rather than an error that invites duplicate sends. Recovery may show unknown delivery. Never automatically resend an unknown task.
- Accepted waiting observations recover without activating targets. Their original deadline does not reset. Terminal reason, observation time and cursor are retained; delayed notices contain metadata and retrieval instructions rather than pretending to reproduce historical output. Immediate notices may include bounded in-memory output.
- Automatic notice delivery is **at-most-once attempted**, not exactly-once or guaranteed delivery. A durable claim precedes the synchronous inbox call. Crash after claim, uncertain inbox failure, or loss of liveness during claim can lose the notice; recovery marks notification unknown and never retries that claim. Claim-write failure sends nothing and leaves ready metadata available for a later attempt. The owner can inspect tasks explicitly.
- Storage-open/recovery failure fails plugin initialization visibly. There is no silent in-memory production fallback or backup-and-skip archive. Ongoing storage failure suppresses unsafe notices; existing committed metadata remains the recovery point. Cancellation/expiry cannot retract an already claimed/enqueued notice.

## Bounds and retention

- Pending notices (`waiting`/`ready`): **8 per caller, 32 profile-wide**, including unloaded-caller notices. Capacity checks and durable changes are serialized. `notify:false` is tracked without an observer. In-flight prepared rows cannot be evicted.
- Metadata: **64 rows per caller, 256 profile-wide**. Oldest terminal rows can be evicted early for capacity; pending/prepared rows are never silently evicted. A full pending store rejects new sends before activation.
- All metadata has an **absolute 24-hour TTL from reservation**, including deferred notices; updates and restart never extend it. Expired rows are removed at startup, task access/send, and a 60-second maintenance pass while running. Storage outages/Host downtime can delay physical deletion until the next successful cleanup; expired rows cannot dispatch notices. This is bounded coordination state, not an audit log.
- Observation deadline: default 30 minutes, configurable 1 second–1 hour. Native waits use at most 120-second windows; unexpectedly fast repeated timeouts use abortable backoff. No target polling/activation is performed by the retention timer.
- Manual waits: default 30 seconds, max 120 seconds. Wait-many has 1–8 distinct targets, bounded per-target outcomes and a shared timeout; `any` cancels only other observers. Idle can follow failure/abort and is not causal completion. Native single-wait pre-sample timeout can throw.
- Discovery: default 30/max 100 rows; ordering may change between pages. Task pages default 20/max 64. Project session counts are membership counts, not guaranteed visible ordinary sessions.
- History: default 10/max 50 native message budget, max 100 returned records, default 12,000/max 32,000 text characters. Chronological returned records prioritize newest content for budget. Cold preparation may still load underlying logs. Reasoning/attachments omitted; tool markers opt-in, never payloads. `throughSeq` freezes the cursor and `nextBeforeSeq` retrieves older events; individually truncated text is not chunk-retrievable.
- Persisted active goals are not proof of live execution or armed continuation. Tool abort stops read/manual observation and prevents enqueue when detected before the boundary, not activation already underway. Detached watches survive send-tool completion; plugin disposal aborts observers, preserves durable state and never cancels target execution.

## Packaging and verification

The bundle mounts one Host plugin. Version 0.3.1 owns domain acquisition and sequential asynchronous cleanup through a Cordis effect, including failed setup and unload during initialization. Ordinary `ctx.on('dispose')` listeners are not lifecycle disposers. Upgrading a Host that already leaked an open domain under 0.2.1/0.3.0 requires a Host restart after installing the repair; do not close an unknown shared handle, erase storage, or repeatedly hot-retry. This fix preserves the domain name/version and stored records.

Exact runtime peers: LLM, session-title, storage-domain and Zod. `sessionTitle` is a hard injected dependency (the plugin cannot activate without it); no duplicate native implementation, build script or client code. Use the maintained MAINFRAME DSH installer; do not manually alter profile storage/configuration.

```sh
node --test plugins/dsh/session-collaboration/*.test.js
node --check plugins/dsh/session-collaboration/index.js
```

The exported `selftest.js` probe uses synthetic in-memory services/Agents only: no models, real sessions or profile mutations. Development tests cover crash boundaries, acknowledgement/claim failures, abort/disposal, duplicate suppression, restart/deadline/TTL, unloaded/replaced caller, ownership and capacity. Model tests cover the public `{agent}|{error}` resolve result, validation before mutation, Auto omission, passive cold reads, target replacement/archive checks, concurrent complete selections, uncertain outcomes and disposal draining. They do not establish native persistence or runtime/model behavior; selection-event persistence is based on the documented public Agent contract, and real-agent acceptance remains separate.

The 0.5.1 first-turn tool-definition JSON (compact array of `name`, `description`, `parameters`) is **4,936 characters / 4,938 UTF-8 bytes across one tool**, versus 4,746 / 4,748 in 0.5.0: **+190 characters/bytes** for explicit naming (about 4%). The earlier eight-tool 0.4.0 surface was 8,912 characters / 8,936 bytes. These are schema-size measurements, not prompt-token counts; no compatible tokenizer is installed locally. Model catalogs, efforts, selected histories and tracking rows remain deferred to bounded discovery results rather than repeated in the initial prompt.

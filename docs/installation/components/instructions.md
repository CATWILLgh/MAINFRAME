# Adapt the global instruction

Use this guide for `instructions.global`. Install it after component identities,
paths, and permissions are known so its references describe the effective
installation.

## Resolve the owner

Use current native documentation and a fresh-session probe to find the effective
global instruction owner and precedence. Inspect only the files that actually
affect the installed product. A repository root instruction such as MAINFRAME's
own `AGENTS.md` or `CLAUDE.md` is project control-plane support, not the global
destination.

## Merge by semantics

Preserve every unrelated user-owned rule. Reconcile one identifiable
MAINFRAME-owned semantic section from
[instructions/global.md](../../../instructions/global.md):

- update an existing owned section in place;
- do not append a duplicate because formatting changed;
- do not install compatibility copies into several global instruction systems;
- add native wrapper syntax only to the installed owner;
- keep project facts and target-only paths out of canonical source.

If an existing user rule and the canonical instruction make incompatible
semantic demands, stop on the exact conflict. Do not silently choose, weaken
both into vague wording, or overwrite the user's rule.

## Verify

Validate native syntax and effective precedence. Start a new session when the
product reads instructions only at launch. Use a harmless question or diagnostic
that demonstrates the relevant MAINFRAME rule is active and the preserved user
instruction still applies.

Do not claim success from finding the text on disk. Record the effective owner,
reload boundary, preservation evidence, and any instruction-only limitation.
